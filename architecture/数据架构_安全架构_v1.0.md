### 1.2 SQLite Schema 详细设计

#### 1.2.1 jobs 表 — 任务定义

```sql
CREATE TABLE IF NOT EXISTS jobs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(255) UNIQUE NOT NULL,          -- 任务名称（唯一标识）
    description TEXT DEFAULT '',                 -- 任务描述
    trigger_type VARCHAR(20) NOT NULL DEFAULT 'cron',  -- 触发器类型: cron/interval/date
    trigger_config TEXT NOT NULL DEFAULT '{}',   -- 触发器配置（JSON）
    func_ref VARCHAR(512) NOT NULL,              -- 函数引用 module:function
    max_retries INTEGER NOT NULL DEFAULT 3,      -- 最大重试次数
    timeout INTEGER NOT NULL DEFAULT 300,        -- 超时时间（秒）
    idempotency_key_expr VARCHAR(255),           -- 幂等键表达式
    status VARCHAR(20) NOT NULL DEFAULT 'active', -- 状态: active/paused/disabled
    next_run_time DATETIME,                      -- 下次执行时间
    last_run_time DATETIME,                      -- 上次执行时间
    params TEXT DEFAULT '{}',                    -- 默认参数（JSON）
    version VARCHAR(20) DEFAULT '1.0.0',         -- 任务版本
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 索引
CREATE INDEX idx_jobs_status ON jobs(status);
CREATE INDEX idx_jobs_next_run_time ON jobs(next_run_time);
```

**trigger_config JSON 格式示例**：
| 触发器类型 | JSON 示例 |
|-----------|----------|
| cron | `{"hour": "2", "minute": "0", "second": "0"}` |
| interval | `{"hours": "1", "minutes": "30"}` |
| date | `{"run_date": "2026-09-15 10:00:00"}` |

#### 1.2.2 job_executions 表 — 执行记录

```sql
CREATE TABLE IF NOT EXISTS job_executions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    job_id INTEGER,                              -- 关联 jobs.id
    run_id VARCHAR(64) UNIQUE NOT NULL,          -- 运行 UUID（唯一标识）
    trigger_type VARCHAR(20) NOT NULL DEFAULT 'schedule', -- 触发方式: schedule/manual/retry
    scheduled_time DATETIME,                     -- 计划执行时间
    start_time DATETIME,                         -- 实际开始时间
    end_time DATETIME,                           -- 结束时间
    duration REAL,                               -- 耗时（秒）
    status VARCHAR(20) NOT NULL DEFAULT 'running', -- 状态: running/success/failed/dlq/skipped
    retry_count INTEGER NOT NULL DEFAULT 0,      -- 重试次数
    idempotency_key VARCHAR(512),                -- 幂等键
    error_code VARCHAR(20),                      -- 错误码 SCH-XX-YYY
    error_message TEXT,                          -- 错误信息
    result_data TEXT DEFAULT '{}',               -- 结果数据（JSON）
    node_id VARCHAR(128),                        -- 执行节点（主机名）
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 索引
CREATE INDEX idx_exec_job_id ON job_executions(job_id);
CREATE INDEX idx_exec_status ON job_executions(status);
CREATE INDEX idx_exec_start_time ON job_executions(start_time);
```

**状态流转**：
```
           ┌─────── success（成功终态）
           │
running ───┼─────── failed ──→ retrying ──→ ... ──→ dlq（死信终态）
           │
           ├─────── skipped（幂等跳过终态）
           │
           └─────── cancelled（取消终态）
```

#### 1.2.3 idempotency_keys 表 — 幂等键

```sql
CREATE TABLE IF NOT EXISTS idempotency_keys (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    job_id INTEGER,                              -- 关联 jobs.id
    idempotency_key VARCHAR(512) UNIQUE NOT NULL, -- 幂等键（唯一约束）
    status VARCHAR(20) NOT NULL DEFAULT 'success', -- 状态: success
    result_data TEXT DEFAULT '{}',               -- 缓存结果（JSON）
    execution_id INTEGER,                        -- 关联 job_executions.id
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 索引
CREATE INDEX idx_idem_key ON idempotency_keys(idempotency_key);
```

**幂等键格式**：`{task_name}:{表达式结果}`
| 表达式 | 示例键 | 去重粒度 |
|--------|--------|---------|
| `{date}` | `daily_backup:2026-09-02` | 每天一次 |
| `{datetime}` | `hourly_sync:2026-09-02 14:00:00` | 每小时一次 |
| `{weekday}` | `weekday_report:2` | 每周同一天的任务 |
| `{param:region}` | `region_sync:us-east` | 按参数去重 |
| `{date}_{param:type}` | `multi_task:2026-09-02_full` | 日期+参数组合 |

#### 1.2.4 scheduler_state 表 — 调度器状态

```sql
CREATE TABLE IF NOT EXISTS scheduler_state (
    id INTEGER PRIMARY KEY CHECK (id = 1),       -- 单例行（id 恒为 1）
    state VARCHAR(20) NOT NULL DEFAULT 'stopped', -- 状态: stopped/running
    last_heartbeat DATETIME,                     -- 最后心跳时间
    started_at DATETIME,                         -- 启动时间
    version VARCHAR(20),                         -- 调度器版本
    node_id VARCHAR(128),                        -- 节点标识（主机名）
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

### 1.3 CSV 台账格式设计

#### 1.3.1 执行记录台账（台账/31_定时任务执行记录.csv）

| 列序号 | 列名 | 类型 | 说明 | 示例 |
|-------|------|------|------|------|
| 1 | 执行编号 | 文本 | EX-YYYYMMDD-XXXX | EX-20260902-A1B2 |
| 2 | 任务名称 | 文本 | 任务唯一标识 | daily_backup |
| 3 | 运行ID | UUID | 执行唯一标识 | 550e8400-e29b-... |
| 4 | 触发方式 | 枚举 | schedule/manual/retry | schedule |
| 5 | 计划时间 | 时间 | 计划执行时间 | 2026-09-02 02:00:00 |
| 6 | 开始时间 | 时间 | 实际开始时间 | 2026-09-02 02:00:01 |
| 7 | 结束时间 | 时间 | 执行结束时间 | 2026-09-02 02:00:15 |
| 8 | 耗时(秒) | 数值 | 执行耗时 | 14.23 |
| 9 | 状态 | 枚举 | success/failed/dlq/skipped | success |
| 10 | 重试次数 | 整数 | 已重试次数 | 0 |
| 11 | 幂等键 | 文本 | 完整幂等键 | daily_backup:2026-09-02 |
| 12 | 错误码 | 文本 | SCH-XX-YYY 格式 | SCH-00-000 |
| 13 | 错误信息 | 文本 | 错误描述（截断 500 字） | - |
| 14 | 执行节点 | 文本 | 主机名 | MacBook-Pro |
| 15 | 记录时间 | 时间 | 记录写入时间 | 2026-09-02 02:00:15 |

**格式规范**：
- 编码：UTF-8 with BOM（`utf-8-sig`）
- 写入模式：追加（不覆盖）
- 文件不存在时：自动创建 + 写入表头
- 行尾：LF（跨平台统一）

### 1.4 数据生命周期

```
创建 ──→ 活跃使用 ──→ 归档保留 ──→ 清理
 │           │              │            │
 │  新任务注册  │  调度执行中    │  90 天保留   │  过期清理
 │  新执行记录  │  状态更新     │  CSV 永久保留 │  SQLite 清理
 │  新幂等键   │  查询统计     │             │  幂等键清理
```

**清理策略**：
| 数据类型 | 保留策略 | 清理方法 |
|---------|---------|---------|
| job_executions | 90 天（可配置） | `cleanup_old_executions(days)` |
| idempotency_keys | 跟随执行记录 | 随执行记录一起清理 |
| CSV 台账 | 永久保留 | 手动归档/压缩 |
| SQLite 数据库 | 随项目生命周期 | `VACUUM` 优化 |

### 1.5 数据完整性约束

| 约束 | 类型 | 说明 |
|-----|------|------|
| jobs.name UNIQUE | 唯一约束 | 任务名不可重复 |
| job_executions.run_id UNIQUE | 唯一约束 | 每次执行唯一 |
| idempotency_keys.idempotency_key UNIQUE | 唯一约束 | 幂等键不可重复 |
| scheduler_state.id = 1 | CHECK 约束 | 单例状态行 |
| jobs → job_executions | 逻辑外键 | job_id 关联（非强制外键） |
| idempotency_keys → job_executions | 逻辑外键 | execution_id 关联 |

## 第二部分：安全架构

### 2.1 敏感信息分级

| 级别 | 分类 | 处理方式 | 示例 |
|-----|------|---------|------|
| A 级 | 禁止入库 | 绝对不存储到 SQLite/CSV/日志 | 数据库密码、API 密钥、Token、私钥 |
| B 级 | 脱敏入库 | 脱敏后存储（掩码处理） | Webhook URL（仅显示域名）、主机名 |
| C 级 | 正常入库 | 无需脱敏 | 任务名称、执行状态、耗时、错误码 |

### 2.2 脱敏规则

| 数据类型 | 脱敏前 | 脱敏后 | 规则 |
|---------|--------|--------|------|
| API 密钥 | `sk-abc123def456` | `sk-***` | 保留前缀，其余掩码 |
| Token | `Bearer eyJhbG...` | `Bearer ***` | 保留类型，值掩码 |
| URL(含密钥) | `https://x:key@host` | `https://x:***@host` | 密码部分掩码 |
| Webhook URL | `https://hook.xxx/abc123` | `https://hook.xxx/***` | 路径掩码 |
| 密码 | `P@ssw0rd!` | `***` | 完全掩码 |

### 2.4 Git 安全策略

**.gitignore 必须包含**：
```
# 敏感数据
.secrets/
*.db

# 运行日志
logs/

# Python
__pycache__/
*.pyc
*.pyo
*.egg-info/
dist/
build/
.eggs/

# IDE
.idea/
.vscode/
*.swp
```

**安全规则**：
| 规则 | 说明 |
|-----|------|
| A 级信息禁入库 | 密钥/Token/凭据绝对不出现在 Git 跟踪文件中 |
| .secrets/ gitignore | 数据库文件不进入版本控制 |
| logs/ gitignore | 日志文件不进入版本控制 |
| 代码审查 | 提交前检查是否有硬编码密钥 |

### 2.5 执行安全

#### 2.5.1 任务函数执行安全

| 安全措施 | 实现方式 | 说明 |
|---------|---------|------|
| 超时控制 | 线程 join(timeout) | 防止单任务阻塞调度器 |
| 异常隔离 | try/except 包裹 | 任务异常不影响其他任务 |
| daemon 线程 | daemon=True | 进程退出时自动清理 |
| 错误码规范 | SCH-XX-YYY | 统一错误分类和追溯 |

#### 2.5.2 数据安全

| 安全措施 | 实现方式 | 说明 |
|---------|---------|------|
| 幂等保护 | UNIQUE 约束 | 防止重复执行产生副作用 |
| 事务保护 | BEGIN/COMMIT/ROLLBACK | SQLite 操作原子性 |
| WAL 模式 | PRAGMA journal_mode=WAL | 崩溃恢复 |
| 线程安全 | threading.Lock | 并发写入保护 |

#### 2.5.3 告警安全

| 安全措施 | 实现方式 | 说明 |
|---------|---------|------|
| 降级策略 | 告警失败不阻塞 | SCH-08-001 |
| 频率控制 | 5 分钟最小间隔 | 防止告警风暴 |
| Webhook 超时 | 30 秒超时 | 防止网络阻塞 |
| 信息脱敏 | 错误消息截断 200 字 | 防止敏感信息泄漏到通知渠道 |

### 2.6 安全审计追溯

所有安全相关事件通过以下机制追溯：

| 审计渠道 | 记录内容 | 存储位置 |
