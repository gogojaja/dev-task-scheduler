## 第一部分：C4 模型

### C4 Level 1 — 系统上下文图

```
┌─────────────────────────────────────────────────────────────┐
│                    用户（Python 开发者/DevOps）                │
│         通过 CLI / Python API / YAML 配置 交互               │
└──────────────┬──────────────────────────────┬────────────────┘
               │ 命令/代码调用                  │ 配置修改
               ▼                              ▼
┌──────────────────────────────────────────────────────────────┐
│              dev-task-scheduler (本系统)                       │
│    轻量、可靠、可观测的本地定时任务调度框架                        │
│    ────────────────────────────────────────────               │
│    • 定时任务注册与调度（cron/interval/date）                    │
│    • 幂等校验 + 重试策略 + 死信队列                              │
│    • 状态持久化 + 执行记录审计                                   │
│    • 告警通知 + 超时控制                                       │
│    • 跨项目复用（PROJECT_ROOT）                                 │
└──────────────┬──────────────────────────────┬────────────────┘
               │ 调用                          │ 通知
               ▼                              ▼
┌──────────────────────────┐    ┌──────────────────────────────┐
│   APScheduler 3.11.3     │    │  外部告警目标（可选）            │
│   （调度内核依赖）          │    │  Webhook URL（钉钉/飞书等）    │
└──────────────────────────┘    └──────────────────────────────┘
```

**外部实体**：
| 实体 | 类型 | 交互方式 | 必要性 |
|-----|------|---------|--------|
| Python 开发者 | 用户 | CLI / Python API / YAML | 必须 |
| APScheduler 3.11.3 | 依赖库 | Python import | 必须 |
| PyYAML | 依赖库 | Python import | 必须 |
| Webhook 目标 | 外部系统 | HTTP POST | 可选 |
| 外部项目 | 被调度项目 | PROJECT_ROOT 环境变量 | 可选 |

### 视图 2 — 进程视图（运行时并发模型）

```
┌─────────────────────────────────────────────────────────────────┐
│                        进程视图                                  │
│                                                                 │
│  ┌─── 主进程 ──────────────────────────────────────────────┐    │
│  │                                                         │    │
│  │  ┌─── 主线程 ──────────────────────────────────────┐    │    │
│  │  │  • CLI 命令处理 / 信号处理                        │    │    │
│  │  │  • 调度器启动/停止控制                             │    │    │
│  │  │  • 前台运行时的 sleep 循环                        │    │    │
│  │  └─────────────────────────────────────────────────┘    │    │
│  │                                                         │    │
│  │  ┌─── APScheduler 内部线程池 ──────────────────────┐    │    │
│  │  │  (ThreadPoolExecutor, max_workers=10)            │    │    │
│  │  │                                                  │    │    │
│  │  │  ┌──────────┐ ┌──────────┐ ┌──────────┐        │    │    │
│  │  │  │ Worker-1 │ │ Worker-2 │ │ Worker-N │        │    │    │
│  │  │  │ 任务A执行 │ │ 任务B执行 │ │ 任务X执行 │        │    │    │
│  │  │  └──────────┘ └──────────┘ └──────────┘        │    │    │
│  │  │                                                  │    │    │
│  │  │  每个 Worker 内部：                               │    │    │
│  │  │  ┌─ daemon 子线程（任务函数执行，超时控制用）─┐    │    │    │
│  │  │  │  func() 或 func(context)                   │    │    │    │
│  │  │  └───────────────────────────────────────────┘    │    │    │
│  │  └──────────────────────────────────────────────────┘    │    │
│  │                                                         │    │
│  │  ┌─── 心跳定时器 ──────────────────────────────────┐    │    │
│  │  │  threading.Timer(60s, heartbeat_tick)            │    │    │
│  │  │  daemon=True, 每 60 秒更新 SQLite 心跳           │    │    │
│  │  └─────────────────────────────────────────────────┘    │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                 │
│  并发控制策略：                                                   │
│  ├── SQLite: threading.Lock 保证线程安全                          │
│  ├── CSV: 追加写入，单线程写入（executor 串行化）                   │
│  ├── 告警: _last_alert_time 字典 + 5 分钟间隔控制                 │
│  └── 调度器状态: _lock (threading.Lock) 保护 start/stop          │
└─────────────────────────────────────────────────────────────────┘
```

**关键并发场景**：
| 场景 | 并发模型 | 保护机制 |
|-----|---------|---------|
| 多任务同时触发 | APScheduler 线程池分发 | max_workers=10, 每任务独立 Worker |
| SQLite 并发写入 | 多线程竞争 | threading.Lock + WAL 模式 |
| CSV 追加写入 | 顺序追加 | 执行框架串行化 |
| 心跳与任务执行 | 并发 | daemon Timer 独立运行 |
| 告警频率控制 | 多线程读取字典 | 字典操作原子性（CPython GIL） |

### +1 场景视图（关键用例）

#### 场景 1：装饰器注册 + 定时调度

```
用户代码                     框架内部
────────                    ────────
@register_task(              
  name="daily_backup",      
  trigger="cron",           
  hour=2, minute=0,         
  idempotency_key="{date}"  
)                           
def daily_backup():    ──→  TaskRegistry.register_function()
  ...                         └→ StateStore.upsert_job()
                              
scheduler.start()      ──→  SchedulerManager.start()
                              └→ _load_registered_tasks()
                                   └→ APScheduler.add_job(CronTrigger)
                              └→ _start_heartbeat()
                              
# 凌晨 2:00 触发          ──→  _execute_job_wrapper("daily_backup")
                              └→ TaskExecutor.execute_task()
                                   ├→ IdempotencyManager.generate_key()
                                   ├→ IdempotencyManager.check() → miss
                                   ├→ StateStore.create_execution(running)
                                   ├→ _run_with_timeout(daily_backup)
                                   ├→ StateStore.update_execution(success)
                                   ├→ IdempotencyManager.record()
                                   └→ RecordWriter.append_record(CSV)
```

#### 场景 2：幂等去重

```
第一次执行（09:00）          第二次执行（09:30，misfire 补发）
──────────────             ──────────────
generate_key() →            generate_key() →
  "daily_backup:2026-09-02"   "daily_backup:2026-09-02"  (相同!)
check() → miss              check() → HIT!
execute task...             return SKIPPED
record key                  不执行，记录 SKIPPED
```

#### 场景 3：重试 + 死信队列

```
第 1 次执行失败
  └→ retry_count=0, should_retry(0, False) → True
  └→ delay = 60 × 2^0 + random(0,30) = ~75s
  └→ 等待 75s...

第 1 次重试失败
  └→ retry_count=1, should_retry(1, False) → True
  └→ delay = 60 × 2^1 + random(0,30) = ~135s
  └→ 等待 135s...

第 2 次重试失败
  └→ retry_count=2, should_retry(2, False) → True
  └→ delay = 60 × 2^2 + random(0,30) = ~255s
  └→ 等待 255s...

第 3 次重试失败
  └→ retry_count=3, is_dead_letter(3, False) → True
  └→ status = DLQ
  └→ Notifier.alert_task_dlq()  ← 严重告警
```

#### 场景 4：崩溃恢复

```
进程异常退出                    进程重启
──────────                   ────────
SQLite WAL 自动回滚             scheduler.start()
未完成的事务恢复                 └→ StateStore 初始化
                                └→ _load_registered_tasks()
                                     └→ 从 Registry 重新加载所有活跃任务
                                └→ APScheduler.start()
                                     └→ 任务恢复调度（<5s）
```
